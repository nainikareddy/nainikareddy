I build data infrastructure that's meant to be used by AI agents, not just people. Pipelines, schema catalogs, and evaluation setups that still hold up when an LLM is making some of the calls, not just when I'm watching it work.

Before this I was the founding GTM engineer at an early-stage B2B SaaS company, building the CRM and lead-scoring systems the revenue team actually ran on. That's where I got interested in the harder version of this problem: it's easy to trust a tool when you're the one using it. It's a different thing to build one that other people, or now agents, have to trust without watching you build it.

## What I've been building

**[LineageIQ](https://github.com/nainikareddy/LineageIQ)**
An auditor for BI sprawl: the duplicate dashboards, broken data connections, and quietly-disagreeing metrics that pile up as a company's reporting grows. The part I actually care about isn't the auditing, it's that I didn't trust the tool until I'd tested it. I planted 7 known problems and 5 realistic decoys into a fake company's data, and only believed the results once it caught all 7 real ones and none of the decoys.

**[Stackatlas](https://github.com/nainikareddy/Stackatlas)**
An MCP server that gives an AI agent an actual map of a messy Postgres database, so it stops guessing what a table is for based on its name.

**[gtm-engineering](https://github.com/nainikareddy/gtm-engineering)**
The go-to-market systems I built and ran as the first GTM engineer at an early-stage startup: CRM integration, lead scoring, account health scoring, some SEO tooling for the AI-answer-engine era. This is the public version, cleaned of anything proprietary.
